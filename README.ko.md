# test-osterone

**테스트는 AI가 작성하고, 판정은 결정적 엔진이 내립니다.**

스프레드시트로 작성한 테스트 케이스를 AI 에이전트가 읽어 assertion을 만들고 셀렉터를 자가복구하며, 결정적 엔진이 매 실행 동일하게 pass/fail을 판정합니다.

## 왜 만들었나

테스트 자동화는 두 가지 비용에서 막힙니다. **작성**(케이스와, 각 테스트 단계가 화면의 요소를 집어내도록 가리키는 *셀렉터*를 쓰는 일)과 **유지보수**(그 셀렉터가 낡는 일 — 화면이 조금만 바뀌어도 테스트가 누르던 버튼·입력창을 못 찾아, 기능은 멀쩡한데 테스트가 깨진다)입니다. test-osterone은 이 둘을 AI 에이전트에 맡겨, 비개발자도 스프레드시트만으로 회귀 테스트를 돌릴 수 있게 합니다. 단, 절대 추측이어서는 안 되는 한 가지 — **판정** — 만큼은 결정적으로 지킵니다.

이름은 *testosterone*의 말장난입니다(`test` + `osterone`). 페르소나 **"테토"** 는 단호합니다. 조용히 틀린 pass를 내느니 케이스를 리뷰로 넘깁니다. **false-pass = 0** 이 최우선 목표입니다.

## 핵심 분리 — *작성하는* 에이전트, *판정하는* 엔진

| 층위 | 담당 | 사람 개입 |
|---|---|---|
| 작성 | AI가 시트 해석 규칙 확립, 케이스→assertion(합격·실패를 가르는 구체 검증 조건) 작성, 자동화 가능 여부 선별, 셀렉터 자가복구 | 규칙/첫 baseline **1회 승인**(선택) |
| 실행·판정 | 결정적 엔진 — 매 실행 동일한 결론 | **없음 — 완전 자동** |
| 예외 | 확신하지 못하는 케이스만 `needs_review` | 애매한 소수만 **한 번** 확인 후 자동화 |

> 전체를 "판정까지 하는 에이전트"로 뭉뚱그리지 않습니다. **판정의 결정성**이야말로 배포 게이트로 쓸 만큼의 신뢰를 만들기 때문입니다.

### 결정성을 보장하는 방법

- **1회 작성, 캐시 유지.** assertion은 `(caseId + ruleId + ruleVersion + caseHash)` 키로 한 번 작성한 뒤 캐시합니다. 재실행은 캐시를 *평가만* 하므로 결론이 동일합니다. 규칙이나 케이스가 바뀌면 키가 바뀌어 재작성됩니다(캐시 무효화).
- **self-heal 게이트.** 셀렉터 자가복구가 일어난 실행은 자동 통과가 금지되고 `needs_review`로 갑니다.
- **baseline.** 시각적·애매한 케이스는 사람이 승인한 골든 baseline과 (동적 영역은 마스킹한 채) diff합니다. 미승인이거나 드리프트가 감지되면 `needs_review`로 갑니다.
- **원칙:** *거짓 통과를 내느니 needs_review로 넘깁니다.*

## 파이프라인

```
스프레드시트 (XLSX / 구글시트)
  → 정규화 · 중복 제거 (결정적 content-hash)
  → 규칙 확립 (AI 대화형 · 버전 관리 · 영속 · 재사용)
  → 선별 triage (자동화 가능 vs 사람 개입 필요)
  → 해석 (규칙 + 케이스 → 결정적 assertion, 캐시)
  → 실행 (헤드리스 브라우저, 재시도, self-heal 게이트)
  → 판정 (assertion 결정적 평가 + baseline diff + needs_review)
  → 증거 (스크린샷 / DOM + SQLite)
  → 웹 대시보드 (이력 · 판정 · 증거 · needs_review 큐)
```

## 성공 기준 (하드 게이트)

| 지표 | 기준 | 의미 |
|---|---|---|
| 판정 결정성 | **100%** (동일 케이스 K=5회 완전 일치) | 배포 게이트로 쓸 수 있는 재현성 |
| 거짓 통과(false-pass) | **0** (벤치마크 하드 게이트) | 조용히 틀린 pass가 최악의 결과 — 최우선 차단 |
| 선별 정확도 | **≥ 90%** (초기 기준, 실측 후 조정) | 자동화 대상 분류가 사람 라벨과 일치 |

## 빠른 시작

```bash
bun install            # 최초 1회 · postinstall이 Playwright Chromium 설치
bun run setup          # 위에서 Chromium이 설치 안 됐으면 명시 실행

bun run studio         # ← 본체: UI 빌드 후 http://localhost:8686 서빙
bun run demo           # 또는 번들 fixture로 파이프라인 실행 관찰 (추가 설정 없이)

```

> **Bun ≥ 1.3** 이 필요합니다. test-osterone은 **Studio 우선** 도구입니다 — 일상 사용은 브라우저 Studio(`bun run studio`)에서 이뤄지고, CLI는 `setup`·`--version`·`--help`만 제공하는 얇은 부트스트랩입니다.

## 직접 돌려보기 — 라이브 데모

테스트할 프로젝트가 아직 없으신가요? 번들된 fixture 앱으로 전체 파이프라인이 **실제 헤드리스**(창 없이 백그라운드로 도는) Chromium을 상대로 도는 모습을 바로 확인할 수 있습니다.

```bash
bun install        # 최초 1회 (postinstall이 Chromium 설치)
bun run demo
```

`src/testing/sample-cases.csv`를 읽어 결정적 assertion을 작성한 뒤, 로컬 로그인 앱을 상대로 네 개의 케이스를 실행합니다.

```
case                                      verdict        conf  assert  heal
Valid login shows welcome                 pass           1.00  2/2     -
Invalid login shows error                 pass           1.00  2/2     -
Wrong password must not pass as welcome   fail           1.00  0/2     -
Missing button triggers self-heal gate    needs_review   0.50  1/1     click
verdicts    : {"pass":2,"fail":1,"needs_review":1}
determinism : 4/4 identical on rerun OK
false-pass  : 0 OK
```

세 번째 케이스는 성공(Welcome)을 *기대*하지만 틀린 비밀번호를 넣습니다 — 엔진은 거짓 통과 대신 `fail`을 냅니다. 네 번째는 없는 셀렉터를 클릭하는데, self-heal 게이트가 이를 `needs_review`로 묶습니다. 다시 돌려도 모든 판정이 완전히 동일합니다.

내 사이트로 바꾸려면 케이스 파일을 만들고 베이스 URL을 넘기면 됩니다.

```bash
bun run run:live -- --url https://your.app --cases ./my-cases.csv
```

> **Node ≥ 22.7** 이 필요합니다. Playwright의 브라우저 런치가 현재 Windows의 Bun에서 멈추기 때문에, 데모는 브라우저를 Node(`node --experimental-transform-types`)로 실행합니다. CLI와 결정적 엔진은 Bun 위에서 동작합니다.

### 모델 연결 (전역, 톱바)

로그인형 컨트롤(● 상태 + 모델명)을 누르면 세 가지 모드의 모달이 열립니다.

- **ChatGPT 로그인** — 브라우저에서 OpenAI **디바이스 코드** OAuth로 진행합니다. **`codex` CLI가 필요 없으며**, 로컬 `codex` 세션이 있으면 자동 감지합니다.
- **토큰 직접 입력** — 선택적으로 모델 오버라이드를 함께 지정합니다.
- **API Key / 엔드포인트** — model + Base URL로 *임의의* OpenAI 호환 엔드포인트(Azure OpenAI, OpenRouter, Together, 로컬 vLLM/Ollama)에 연결합니다.

추론 모델에는 선택적으로 **추론 수준**(minimal/low/medium/high/xhigh/max)을 적용할 수 있습니다. 모델은 항상 **작성 시점**에만 쓰이고 판정에는 절대 개입하지 않습니다.

### 내비게이션 & 레이아웃

- **톱바** — 브랜드 마크·제품명·전역 모델 연결 상태·**KO/EN 언어 토글**. 브랜드를 누르면 환영 화면으로 돌아갑니다.
- **컨텍스트 스트립** — 가로형 **프로젝트 | 시트** 스트립에서 활성 프로젝트와 시트를 고르거나 전환하며, 둘 다 **바로 추가/수정/삭제**할 수 있습니다(프로젝트 편집기 모달과 시트 편집기 모달 — 별도 "관리" 화면 없음).
- **뷰 레일** — 시트를 선택하면 콘텐츠 옆 **좌측 세로 레일**(모바일에서는 하단 도크)이 네 가지 시트 범위 뷰 — **대시보드, 규칙, 실행 & 결과, 리뷰** — 를 노출합니다. 각 뷰는 자체 제목과 `프로젝트 · 시트` 컨텍스트 줄을 가집니다.
- **명시적 드릴다운** — 프로젝트가 없으면 (forged 로고 브랜드 히어로가 있는) **환영 화면**에서 프로젝트를 고르거나 새로 만듭니다. 프로젝트는 있지만 시트가 없으면 **프로젝트 홈**이 해당 프로젝트의 시트를 선택 가능한 그리드로 보여줍니다(시트가 없으면 첫 시트 추가 안내). 시트를 고르면 네 뷰가 열리고, 활성 프로젝트를 삭제하면 환영 화면으로 돌아갑니다.
- **데이터 모델** — **프로젝트**는 하나 이상의 1급 **테스트 시트**(구글 시트 URL / CSV 붙여넣기 / `.xlsx` 업로드)와 공유 기본값(대상 URL, 환경, **계정 풀**, 참고 repo, AI 토글)을 갖습니다. 각 **테스트 시트**는 대상 URL·환경·열 매핑·기본 계정을 독립적으로 **오버라이드**할 수 있습니다.
- **시트 개수 캡 없음** — 시트 목록이 8개를 넘으면 검색/필터가 나타나고, 활성 항목은 자동으로 스크롤되어 보이며, 좁은 화면에서는 컨텍스트 스트립이 반응형으로 바뀌고, 긴 이름에는 툴팁이 붙습니다.

### 시트 다루기

- **시트별 런타임** — 모든 시트는 **자신만의 실행 이력과 리뷰 대기열**은 물론 **자신만의 해석 규칙·다듬기 대화·승인된 기준 화면**을 갖습니다(프로젝트는 새 시트가 복제해 가는 **기본 규칙**과, 업그레이드 이전 승인을 위한 **레거시 기준 화면 폴백**을 유지합니다). 대시보드는 선택된 시트의 데이터와 함께 간결한 **프로젝트 롤업**(시트 전체 합격률 집계)을 보여주고, 리뷰 네비 배지는 **선택된 시트**의 대기열을 셉니다(실행 중 실시간 갱신). 시트를 실행하면 그 시트만 인제스트됩니다(시트별 dedupe).
- **AI 시트 해석** — 시트를 추가하면 **3단계 온보딩 마법사**가 실행됩니다: **원본** 선택(구글 시트 URL / CSV / `.xlsx`) → 모델이 **해석 제안**(열 매핑 `id/title/step/expected/priority/…` → 실제 헤더명, 케이스 미리보기 포함) → **대화형 다듬기** 단계에서 자연어로 조정("소분류 말고 중분류를 제목으로"). 결과 규칙은 **시트별로** 저장되어 해당 시트의 인제스트에 적용되며, 이후에도 규칙 뷰에서 계속 다듬을 수 있습니다.
- **파일 1개 = 시트 1개 · 내부 카테고리** — `.xlsx`를 가져오면 **파일당 시트 1개**로 매핑됩니다(탭들은 병합되고, 각 탭 이름은 `분류` 카테고리 컬럼으로 캡처). 카테고리 컬럼 또는 `[말머리]` 제목 접두가 케이스를 **카테고리**로 묶고, 미리보기·결과·대시보드·리뷰 전반에 카테고리별 개수와 함께 배지로 표시됩니다. 병합은 **레코드 단위**입니다 — QA 시트의 예상결과는 여러 줄이라, 줄 단위로 탭 이름을 붙이면 따옴표 안에 그 문자열이 주입됩니다. 열 감지는 **열 순서가 아니라 별칭 우선순위**를 따르므로 사전조건이 시험절차보다 앞에 있어도 스텝은 *절차* 열로 매핑되고, 제목·절차·예상결과가 모두 빈 행(서브헤더 띠, 구분선)은 리뷰 큐의 영구 노이즈가 되지 않도록 버립니다.
- **대화형 규칙 다듬기** — 모델 연결 후 **AI 규칙 다듬기**로 선택된 시트의 규칙을 자연어로 다듬습니다(예: "누르기도 click으로 인식해"). 대화식이라 이전 턴을 이어받고("그건 되돌려"), 매 턴마다 **intent diff**와 **모호·빈 intent 경고**를 보여줘 규칙이 최적의, 해석 가능한 형태로 수렴합니다. 변경은 해당 시트의 규칙 버전을 올리며, **초기화**로 대화를 리셋합니다.

### 실행

- **실행** — 프로젝트와 시트를 고르고 **실행**을 누릅니다(**AI 스텝 해석**은 기본 켜짐). 결과는 **케이스 단위로 스트리밍**되어(NDJSON) 각 케이스가 끝나는 즉시 판정과 pass/fail/needs_review 집계가 실시간으로 갱신됩니다.
- **AI 스텝 해석** — 켜면 연결된 모델이 따옴표도 DSL도 없는 자유 자연어 스텝을 결정적 계획(actions + assertions)으로 바꿉니다. 계획은 **1회 작성 후 캐시**되고 엔진이 결정적으로 재생합니다 — `pass` / `fail` / `needs_review` 의미 동일, false-pass 0 유지. 번들 샘플에 따옴표 없는 변형이 포함되어 바로 확인할 수 있습니다. **모델이 연결돼 있지 않으면** 안내와 함께 규칙 해석으로 **소프트 폴백**하며, Codex/ChatGPT 로그인은 **서버 시작 시 자동 복원**됩니다.
- **계정 풀 + 역할 라우팅** — 프로젝트가 **계정 풀**을 갖고, 각 시트는 기본 계정을 연결하며, 각 케이스는 자신의 `role`에 맞는 계정으로 라우팅됩니다(레거시 username/password는 단일 계정으로 마이그레이션).
- **실행 모드** — 단일 시트 또는 **전체 시트 일괄 실행**(`run-all`: 시트별 스트림 + 집계 판정)을 지원하며, **헤디드** 토글로 보이는 Chromium(slowMo)을 지켜볼 수 있습니다.
- **로그인은 사전조건이 아니라 지연 실행** — 엔진은 **세션이 실제로 필요한 케이스에서만** 로그인합니다. 로그인 페이지 검증에 로그인이 선행되면 안 되니까요 — 앞쪽 케이스가 **로그인** 케이스면 그 앞에서 인증하지 않습니다. 세션이 필요한 시점의 로그인은 클라이언트 렌더링(SPA) 화면이 뜰 때까지 대기하고, 화면에 실제로 그려진 문구(띄어쓰기·문장부호 차이 허용, 입력 가능한 요소만)에 맞춰 입력한 뒤 폼이 사라질 때까지 폴링하며, 실패하면 앱이 띄운 안내 문구를 그대로 알려줍니다. 한 번도 인증되지 않으면 케이스를 하나씩 리뷰 큐에 흘려보내는 대신 그 사유로 실행을 중단합니다.
- **스텝 회복 사다리** — 스텝이 실제 화면과 어긋나면 그냥 넘어가지 않습니다. (1) 입력을 가로채는 모달·공지 팝업을 닫고 화면을 안정시킨 뒤 **1회 재시도**, (2) 모델이 연결돼 있으면 **실행 중에 개입**해 현재 화면을 다시 읽고(구조 스캔 + 스크린샷) 교정된 동작을 받되 **그 화면에 실제로 존재하는 라벨·경로일 때만** 채택(케이스당 2회 예산), (3) 그래도 안 되면 나머지 스텝을 **중단**합니다 — 계획이 가정한 화면이 아닌 곳에서 엉뚱한(때로는 파괴적인) 클릭이 이어지는 것을 막습니다. 모든 단계는 heal 이벤트로 남아 회복된 케이스도 `needs_review`로 캡(false-pass 0 유지)되고, 무엇을 교정·건너뛰었는지 리뷰 화면이 그대로 설명합니다. 규칙이 해석하지 못한 스텝도 조용히 넘기지 않고 기록합니다.
- **케이스 사이 회복** — 케이스들은 브라우저 세션 하나를 공유하므로, 중단된 케이스를 방치하면 이후 케이스가 전부 오염됩니다. 중단·오류로 끝난 케이스 뒤에는 **알려진 화면으로 초기화**하고, 앱이 로그인 화면으로 튕겨냈으면 **재로그인**(횟수 제한)한 뒤 진행하며 그 사실을 실행 알림으로 알려줍니다.
- **경로 검증** — 모든 `goto`를 실제 도착지(최종 URL + 문서 상태)와 대조합니다. **인증 튕김**(`/approvals` → `/auth/login?returnUrl=…`)이나 **4xx 경로**는 스텝 실패로 처리해 회복 사다리로 넘깁니다 — 나머지 스텝이 로그인 화면을 상대로 조용히 돌아가는 일이 없습니다. 정상 리다이렉트(`/orders` → `/orders/list`, 루트 → 진입 화면)는 건드리지 않습니다. 라이브 정찰은 nav 라벨뿐 아니라 앱의 **실제 경로**를 계획 작성 모델에 넘기므로, 로그인이 `/auth/login`인 앱에 `/login`을 지어내지 않습니다.
- **세션 소유권은 실행기에** — 누가 로그인돼 있는지는 케이스가 아니라 실행기가 정합니다. **로그인/인증** 케이스는 매번(첫 케이스만이 아니라) 쿠키·웹 스토리지를 비운 상태에서 시작해 진짜 로그인 폼을 만납니다. 나머지 케이스는 **자신의 `role`이 가리키는 계정으로 실제 로그인**한 상태에서 돌고, 현재 세션이 다른 사용자면 갈아탑니다 — 역할에 맞는 자격증명을 계획문에 넣어주는 것과 그 사용자'로서' 도는 것은 전혀 다르고, 관리자 케이스를 뷰어 세션으로 돌리는 순간 권한 테스트는 조용히 거짓말을 합니다. **로그아웃** 케이스는 로그인된 상태에서 시작해 세션을 끊고, 다음 케이스는 자동으로 다시 로그인합니다. 로그인이 안 먹으면 **1회 재시도**하되 앱이 **명시적으로 거부한 자격증명은 재제출하지 않으며**(계정 잠김 방지), 2회 실패하면 남은 케이스마다 로그인 타임아웃을 태우지 않고 포기합니다.
- **실행 수명주기** — 실행은 **서버 측에서 유지**됩니다: 새로고침하거나 재접속해도 계속 진행되고(실행 벤치가 다시 붙어 실시간 진행을 보여줌), **중지** 버튼으로 진행 중인 실행을 깔끔하게 취소합니다.

### 라이브 정찰 & 레포 맥락 (정확도 레버)

규칙 뷰에서 실행합니다.

- **라이브 앱 분석**(`reconApp`) — 시트 계정으로 로그인해 앱 구조(내비·폼 필드·버튼·표 헤더)를 스캔하고, 간결한 한국어 도메인 브리프로 축약해 시트의 **appContext**를 채웁니다.
- **레포 코드 분석**(`repo-recon`) — 프로젝트의 참고 repo를 확보(로컬 경로 / 캐시 / shallow clone, 선택적 토큰 + 재클론)하고, **CodeGraph** CLI가 설치돼 있으면 **먼저 클론을 인덱싱**(init/clone 또는 캐시 동기화, 로컬은 절대 안 함)한 뒤 스캔(AGENTS.md·README·라우트·컴포넌트)하고 CodeGraph 탐색 결과를 접어 넣어 코드 브리프로 축약해 시트의 **codeContext**를 채웁니다. CodeGraph는 선택적 재료이며, 없어도 일반 스캔은 그대로 돕니다.

둘 다 **작성 시점**에 돌고, 저장 전 사람이 검토하며, 플랜 작성에만 주입되므로 결정성에는 영향이 없습니다.

### 리뷰 대기열

`needs_review` 케이스가 **스크린샷**·페이지 텍스트·**쉬운 말 사유**(왜 사람이 봐야 하는지: 실행하지 못한 스텝, 확인이 필요한 AI 교정, 아무것도 구분하지 못하는 검증, 적힌 결과 중 일부만 검사됨, 비전 불일치, 기준 화면 미승인) 증거와 함께 표시됩니다. 기준 화면(해당 케이스의 승인된 **레퍼런스 화면**)을 한 번 승인하면, 같은 케이스 콘텐츠를 공유하는 **모든 시트에서** 매치되는 재실행이 **통과**합니다(reconcile-on-read — 목록을 열 때 자동으로 다시 확인 — 가 재실행 없이 다른 시트의 오래된 리뷰 대기 항목을 정리). 페이지가 바뀌면 다시 표시됩니다. 이 승인을 정직하게 유지하는 두 규칙이 있습니다: 스텝이 **미해석·실패·중단**된 케이스는 기준 화면으로 **승인할 수 없고**(실행되지 않은 케이스가 멈춘 화면은 아무것도 증명하지 않습니다), **일괄 승인은 없습니다** — 승인은 화면 하나에 대한 판단입니다. 승인으로 통과한 `pass`는 **그렇게 표시**됩니다. 승인은 그때 그 빌드를 보고 사람이 한 번 내린 판단이기 때문입니다.

증거 처리는 견고합니다: 프로젝트가 켜면 텍스트 assertion은 **관대하게**(공백·문장부호 무시) 매치되고, **입력란에 타이핑한 값**으로도 충족될 수 있으며(`<input>`의 현재 값은 어떤 DOM 텍스트 노드에도 없어서 "입력 제한되어야 한다" 류가 검증 불가였습니다), 존재 검증은 케이스가 **거쳐온 어느 화면**에서든 충족됩니다 — 나타났다 사라진 토스트도 인정되고, "…종료되어야 한다"는 여전히 최종 화면으로 판정합니다. DOM이 기대를 확인할 수 없을 때는 **비전** 패스가 스크린샷을 읽지만, 그 답은 **판정을 내리지 않고 케이스를 사람에게 넘깁니다**. 모델의 이미지 판독은 힌트이고, 판정은 엔진의 검사입니다. 신뢰 모델의 human-in-the-loop 그대로 — 애매한 소수만 한 번 승인하면 이후는 자동이며, 조용한 거짓 통과는 없습니다.

보류된 케이스의 리뷰에는 **Playwright 트레이스**도 임베드됩니다 — 번들 트레이스 뷰어를 **동일 오리진**으로 서빙(공개 뷰어의 Private Network Access 차단 회피)하므로, 실행을 행동 단위로 인라인에서 훑어보거나 새 탭에서 열거나 `trace.zip`을 내려받을 수 있습니다. 트레이스는 케이스별로 캡처되며 `needs_review`/`error`에만 보존됩니다(깨끗한 pass는 아무것도 남기지 않습니다).

### 영속화

프로젝트 메타데이터는 `~/.test-osterone/studio-projects.json`에 저장됩니다. 프로젝트별 런타임 상태는 `~/.test-osterone/studio-state/<projectId>.json`에 **시트별** 규칙·다듬기 대화·플랜 캐시·승인된 기준 화면으로 저장되며, 여기에 프로젝트 **기본 규칙**(새 시트가 복제)과 시트별 업그레이드 이전 승인을 위한 **레거시 기준 화면 폴백**이 더해집니다. `STATE_VERSION` v2→v3 마이그레이션이 기존 프로젝트 단위 상태를 이 구조로 **손실 없이, 멱등하게**(두 번 돌려도 결과가 같게) 끌어올립니다. **시트 CSV 본문은 시트별 파일로 분리 저장**되어(`sheet-data/<projectId>/<sheetId>.csv`) 어느 파일도 시트 개수에 비례해 커지지 않습니다 — 시트 개수 캡이 없는 이유입니다. `baselineKey`/`assertionCacheKey` 포맷은 그대로이므로 false-pass=0이 전 구간에서 유지됩니다.

## 아키텍처

- **런타임:** Node/TS 단일 스택(Playwright)이며, Bun으로 **단일 바이너리**로 배포합니다.
- **러너 계약(seam):** `runScenario(scenario, rule, target) → StructuredResult`. 이 계약이 노드 경계입니다.
- **노드/호스트:** 같은 아티팩트가 **독립 실행(부모)** 또는 **호스트 구동 워커(자식)** 로 HTTP/JSON 위에서 동작하고, 호스트가 결과를 취합합니다. **헤드리스가 기본입니다.**
- **StructuredResult:** `{ verdict ∈ {pass, fail, needs_review, error}, confidence, assertions[], evidenceRefs[], healEvents[], ruleVersion, scenarioHash, executionId, env, … }`.

- **플랫폼** — 웹 대시보드 · 오케스트레이션(노드/호스트) · 인증(API key + OAuth 프록시 + **네이티브 OpenAI 디바이스 코드 로그인**) · JUnit 출력.
- **Studio** — 시트별 1급 런타임 · AI 열 매핑 + 대화형 다듬기 · AI 스텝 해석(플랜 1회 작성, 규칙 소프트 폴백) · 계정 풀 + 역할 라우팅 + **케이스별 지연 세션**(필요할 때 로그인 · 역할에 따라 사용자 전환 · 로그인 케이스는 로그아웃 상태에서 시작) · **스텝 회복 사다리**(오버레이 해제 후 재시도 → 실행 중 AI 교정(화면 근거 필수) → 케이스 중단) · 경로·도착지 검증 · 다중 시트 run-all · 헤디드 실행 · 실행 수명주기(새로고침 유지 · 재접속 · 취소) · XLSX 파일당 시트 1개 임포트 + 내부 카테고리 + 시트별 TC 자동 감지 · KO/EN 토글 + 경로 기반 라우팅 · 라이브 정찰 → appContext(nav 라벨 + **실제 경로**) · 레포 코드 맥락 → codeContext (CodeGraph 옵션) · 팝업·네이티브 다이얼로그 자동 닫기 + 인터랙티브 우선·공백 관대 클릭 · 비전은 판정이 아닌 보류 신호 + 관대 매치 + 입력값 관측 + 비동기 assertion 재시도 · Codex 자동 복원 · Playwright 트레이스 캡처 + 자체 호스팅 트레이스 뷰어.
- **사람 판정 대비 실측** — `bun run measure <projectId> <sheetId>`가 라벨링된 시트를 라이브로 돌려 모든 판정을 시트에 이미 기록된 QA 판정과 대조합니다: `agree` / `false-pass` / `false-fail` / `held`. **사람이 결함으로 기록한 케이스가 초록으로 돌아오면 종료 코드가 0이 아닙니다.** 실제로 일어나지 않은 실행은 채점을 거부하고, false-pass 행에는 **사람이 적은 결함 사유(비고)** 를, false-fail 행에는 **실패한 검사**를 그대로 출력합니다 — 불일치를 케이스별로 파헤치지 않고 한 줄에서 판결합니다.
- **재현되는 실행** — 같은 시트를 같은 앱에 두 번 돌리면 모든 케이스가 같은 판정을 냅니다. 그 경로에 모델 호출 두 개가 앉아 판정을 스스로 흔들고 있었습니다: 애매한 화면에 대한 비전의 판단, 그리고 컨트롤을 기다릴지 포기할지를 가르던 페인트 타이밍 레이스. 이제 비전 답은 (케이스, 기대문) 단위로 기억되고, 부재는 가라앉은 화면에서 확정됩니다. 실측이 의미를 가지려면 먼저 이것이 필요합니다 — **변경을 채택하거나 기각하는 근거가 되는 스코어카드는 자기 자신과 먼저 일치해야 합니다.**

**라이브 검증 완료.** 엔진은 실제 애플리케이션을 대상으로, 실제 브라우저와 실제 모델이 연결된 상태에서 매일 돌아갑니다 — 현재 기준선은 **사람 판정이 달린 98건 QA 시트**이고 `measure`가 끝까지 채점합니다. 그 실측이 말해 주는 것: 남은 불일치는 전부 **시트 대 현실**의 문제(시트가 인용한 문구를 앱이 그 사이 바꿨다)이지 엔진 결함이 아닙니다. `held`는 놓친 게 아닙니다 — 판정을 보류하는 것이 엔진이 제대로 동작하는 모습입니다.

**아직 안 된 것:** 단일 바이너리·데스크톱 패키징, Studio 라이브 화면(CDP screencast), bun 전용 `SqliteEvidenceStore`의 Node Studio 결선.
